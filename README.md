# 说人话

**把 AI 腔中文，改写成中国人真正会说的话。**

An agent skill + zero-dependency CLI that detects and de-slops AI-flavored Chinese writing.

同一件事，两种写法。左边是典型 AI 输出，右边是说人话之后：

> **AI 腔（浓度 100/100）**
>
> 在这个信息爆炸的时代，我们每天都在与海量数据打交道。值得注意的是，绝大多数工具并没有真正解决效率问题……XTool 的出现，不仅是一次产品升级，更是一场工作方式的革命。首先，它快……其次，它稳……最后，它懂你。强大的 AI 引擎会深度理解你的意图，极大地提升你的工作效率。从个人用户到团队协作，再到企业级部署，XTool 构建了完整的生态闭环……让我们一起踏上这段效率之旅，开启智能办公的崭新篇章。未来已来，你还在等什么？

> **人话（浓度 14/100）**
>
> 我用了三天 XTool，说点真实感受。
>
> 快是真的快。原来打开一个 200MB 的文件要 40 秒，现在 5 秒。但"稳"要打个问号——我遇到两次崩溃，都在导入 Excel 的时候，重启后没再犯，暂时观察。
>
> AI 功能只有一处好用：搜文件。用大白话就能找到上个月的合同，不用记文件名。其他 AI 功能像凑数的。
>
> 要不要装？如果你经常翻找旧文件，装。如果只是写写文档，别折腾了。

信息量没变少，废话少了一半，每句话都敢负责。完整对比见 [`examples/before-after.md`](examples/before-after.md)。

## 它能做什么

1. **检测**：`renhua` 是一个零依赖的 Python CLI，给你的中文文本打「AI 腔浓度」分（0-100），逐行标注 24 类病灶；
2. **重写**：`SKILL.md` 让 Claude Code / Codex / Cursor / pi 等任意 coding agent 按流程把病灶清掉——不是换词，是杀腔调、保信息、加判断；
3. **积累**：病灶规则是纯数据（`rules/patterns.txt`），你遇到新的 AI 腔，提一个 PR 就多一条规则。

## 30 秒装上

**给 agent 装（Claude Code / Codex / pi / Cursor 通用）：**

```bash
git clone https://github.com/<you>/shuo-renhua && cd shuo-renhua && ./install.sh
```

装完对 agent 说：「用说人话 skill 改一下这篇文章」即可。

**不装 agent，直接当检测器用：**

```bash
python3 renhua check 你的文章.md
```

评分分档：`0-24 人味` ｜ `25-44 轻度` ｜ `45-69 中度（一眼 AI）` ｜ `70-100 重度（AI 腔晚期）`

## 24 类病灶（精选）

| 类别 | 病灶 | 坏例 → 好例 |
|---|---|---|
| 结构 | 递进对仗链 | 「不仅是一次升级，更是一场思维的革命」→「这次改版解决了一个具体问题：加载太慢」 |
| 结构 | 三连排比 | 「它快、它稳、它懂你」→「它快，这一点没得说；稳不稳还要再观察」 |
| 结构 | 结尾升华 | 「未来已来，你还在等什么？」→「要不要装，看你是不是经常翻找旧文件」 |
| 词汇 | 黑话堆叠 | 「构建了完整的生态闭环」→「插件能互相调用，不用重复写配置」 |
| 词汇 | 万能夸 | 「极大地提升了效率」→「找文件从 40 秒变成 5 秒」 |
| 句法 | 动词名词化 | 「对配置流程进行了优化」→「简化了配置」 |
| 句法 | 翻译腔被动 | 「该方案被广泛应用于各类场景」→「很多团队在用这个方案」 |
| 节奏 | 句子等长症 | 每句都 15 字上下 → 长句铺陈、短句收尾，像说话的呼吸 |
| 装饰 | emoji 装饰 | 「🚀 极致的性能」→「性能：打开 200MB 文件 5 秒」 |

完整规则见 [`rules/patterns.txt`](rules/patterns.txt)——每条都带正则、坏例、好例和修复方向。

## 工作原理：为什么「换个说法」救不了 AI 腔

AI 味的病根不在句法，在**没有可争辩的判断**：句子排序完美、形容词饱满、结构工整，但读完说不出作者到底想说什么。所以本项目的重写流程是：

1. **检测定位** —— `renhua check --json` 拿到病灶清单；
2. **逐类清除** —— 结构毒（排比/递进/升华）先杀，黑话逐个逼问「具体指什么」，逼问不出来整句删；
3. **补回人味** —— 具体的事实（数字、名字、场景）、敢得罪人的判断、长短交错的节奏；
4. **复检** —— 评分压到 25 以下。压不下去通常不是句法问题，是信息密度不够，回去补事实。

只做第 2 步的文章，是「没有 AI 味的空洞」——依然难读。第 3 步才是人话的核心。

> **自指测试**：拿 `renhua` 检测本 README，得分 100——因为里面展示的全部是坏例原文，每一处都被逮住了。工具没有误报。你的文章里如果只有少量引用，评分不受影响；引用大段 AI 文来检测的场景，正好也是你想要的结果。

## 贡献你的病灶

你一定见过没被收录的 AI 腔。规则格式（纯文本，8 个字段）：

```
病灶id || 病灶名 || 类别 || 严重度 || 正则 || 修复方向 || 坏例 || 好例
```

提 PR 前跑一下 `python3 tests/test_detector.py`（会校验每条规则的正则可编译、字段完整）。坏例必须是你真的见过的句子——好例可以造，坏例不能编。
